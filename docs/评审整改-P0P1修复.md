# 评审整改：P0+P1 六项修复

## 背景

阶段一二评审（见 `docs/阶段一二-实现评审.md`）发现以下问题：
- P0-1：where 查询全量 ::text cast，数字/日期区间查询退化为字符串字典序
- P0-2：元数据里的 defaultValue / isReadonly / uuidStrategy 字段在 data 路由没接线
- P1-1：Pool 没有 error 事件监听，业务库断连会崩进程
- P1-2：连接池缓存竞态，并发 miss 泄漏 Pool
- P1-3：零单测，纯函数 bug 藏到评审才暴露
- P1-4：audit 日志泄露 dbConfig 明文密码和 password 列

评审人二轮补充：
- fieldType DB 层没 CHECK 约束，阶段三 DDL 引擎可能遇到未知类型崩掉
- PUT audit 没记 before 快照
- like 没 escape % _ 通配符

本次全部修复。

---

## 变更内容

### 1. P0-1：按 fieldType 重写 where cast 逻辑
- 文件：`src/services/queryParser.ts`
- 整段重写 `buildWhereSql`：删掉全量 ::text hack，改为按 fieldType 决定 cast
  - number → `$N::numeric`
  - date / datetime → `$N::timestamptz`
  - text 类 → `$N::text`
- like 查询 escape % _ \ 通配符，SQL 加 `ESCAPE '\'`
- `buildWhereSql` 签名改为接收 `metaFields` 参数，用于查 fieldType

### 2. P0-2：接上元数据能力
- 文件：`src/routes/data.ts`
- create 流程：
  - 剔除 `isReadonly=true` 的字段
  - 未传字段自动注入 `defaultValue`
  - pk 策略 uuid 时自动 `crypto.randomUUID()`
- PUT 流程：剔除 `isReadonly=true` 的字段

### 3. P1-1 + P1-2：Pool 健壮性
- 文件：`src/services/dbConnection.ts`
- Pool 加 `error` 事件监听，idle client 报错不崩进程
- 缓存 Promise 而非 Pool 实例，并发 miss 不泄漏
- 失败时自动移除缓存，下次请求重试

### 4. P1-3：补单测
- 新增：`test/queryParser.test.ts`（11 个用例）
- 新增：`test/validator.test.ts`（8 个用例）
- 覆盖：where 等值/区间/like escape、sort 解析、注入防护、必填/类型/select/multiselect 校验

### 5. P1-4：audit 日志脱敏
- 文件：`src/utils/audit.ts`
- 新增 `maskDbConfig()`：dbConfig.password 替换为 `***`
- 新增 `maskRow()`：按 fieldType=password 的列名打码
- 文件：`src/routes/projects.ts`
  - project.create / update / delete 的 before/after 全部 maskDbConfig
- 文件：`src/routes/data.ts`
  - data.create / update / delete 的 before/after 全部 maskRow
  - update 前先 SELECT 旧值，补 before 快照

### 6. fieldType DB CHECK 约束
- 直接在 schemaflow_meta 库 ALTER TABLE fields 加 CHECK 约束
- 允许的 13 种类型：text / number / boolean / date / datetime / select / multiselect / json / richtext / file / password / email / url

### 一个观察

项 1 清单写的 `release_year > 2001` 其实区分不了数值比较和字典序——因为数据只有 2001/2003，两种比较结果一样。真正的证据在两处：代码里 `paramCast('number')` 返回 `::numeric`，以及单测断言 `"release_year" > $1::numeric`。如果要端到端验证，下次加个 `release_year > 99` 的用例（数值比较应返回全部 3 行，字典序比较会返回 0 行，因为 `"2" < "9"`）。
