# 阶段一：元数据建模 — 开发记录与验收清单

> 时间：2026-10-25
> 技术栈：Node.js 22 + TypeScript 5.9 + Express 5 + Prisma 7 + PostgreSQL 16

---

## 一、本阶段开发了什么

### 1. 项目骨架

- pnpm + TypeScript + Express 5 + Prisma 7 + PostgreSQL
- 包管理：pnpm，包类型 `module`（ESM）
- 入口：`src/index.ts`，监听 3000 端口
- 环境变量：`.env`（从 `.env.example` 复制），用 `dotenv/config` 加载

### 2. Prisma 元数据层（三张核心表）

- **projects**（项目表）
  - 内部 `id` 自增主键 + 对外 `projectId`（`proj_` + nanoid(16)）
  - `dbType` / `dbConfig`（JSON）/ `status`（软删开关）
  - `created_at` / `updated_at`
- **tables**（表元数据）
  - `(projectId, tableName)` 联合唯一
  - `tableName` 创建后只读
  - `securityConfig` / `viewConfig` 两个 JSON 扩展位
  - 删表时 `onDelete: Cascade` 自动删字段
- **fields**（字段元数据，最核心）
  - `(tableId, fieldKey)` 联合唯一
  - `fieldKey` 创建后只读
  - `fieldType`：13 种枚举（text/number/boolean/date/datetime/select/multiselect/json/richtext/file/password/email/url）
  - `primaryKeyStrategy`：auto_increment / custom / uuid（仅主键字段有值）
  - 约束：isRequired / isUnique / isReadonly / lengthLimit / regex / defaultValue / options(JSON) / sortOrder / extraConfig(JSON)

### 3. REST 接口（嵌套路由）

- **项目层** `/api/projects`
  - `POST` 创建项目（自动生成 `proj_xxx`）
  - `GET` 列表 / `GET /:projectId` 详情
  - `PUT /:projectId` 更新（name/dbType/dbConfig/status）
  - `DELETE /:projectId` 软删（`status=false`）
- **表层** `/api/projects/:projectId/tables`
  - `POST` 建空表（分步建表，不内嵌字段）
  - `GET` 列表 / `GET /:tableName` 详情（带 fields）
  - `PUT /:tableName` 更新 displayName/description/config
  - `DELETE /:tableName` 硬删 + 级联删字段
- **字段层** `/api/projects/:projectId/tables/:tableName/fields`
  - `POST` 加字段
  - `GET` 列表（按 sortOrder 排序）
  - `PUT /:fieldKey` 更新（fieldKey 不可改）
  - `DELETE /:fieldKey` 硬删

### 4. 基础设施

- **占位鉴权中间件**：`Authorization: Bearer <ADMIN_TOKEN>`，从环境变量读，阶段五替换
- **统一响应包装**：`{ code, message, data }`，成功 `code=0`，失败 code=HTTP 状态码
- **zod 入参校验**：每个接口独立 schema，校验失败返回 400 + 字段级错误列表
- **结构化审计 log**：每条 create/update/delete 打一行 JSON 到 stdout，带 timestamp/action/operator/projectId/tableName/fieldKey/before/after
- **dbConfig 存取封装**：`src/services/dbConfig.ts` 两个函数，阶段一明文，未来加密只改这一处

### 5. 工程化配置（对齐 auto-article）

- ESLint 9 flat config + typescript-eslint + import-x 排序 + prettier 兼容
- Prettier：无分号 / 单引号 / printWidth 100 / trailingComma all
- Husky pre-commit：`prisma validate → prisma format → tsc --noEmit → lint-staged`
- lint-staged：`eslint --fix + prettier --write --ignore-unknown`
- npm scripts：`dev / start / build / typecheck / lint / lint:fix / format / format:check / db:g/m/d/validate/format`

## 二、验收清单

> 所有 curl 示例默认 `BASE=http://localhost:3000/api`，`TOKEN=change-me-to-a-long-random-string`（来自 `.env` 的 `ADMIN_TOKEN`）。

### A. 鉴权

| # | 验收项 | 怎么验证 | 预期 |
|---|---|---|---|
| A1 | 无 token 被拒 | `curl -i $BASE/projects` | 401，`{code:401,message:"missing Authorization: Bearer <token>"}` |
| A2 | 错 token 被拒 | `curl -i -H "Authorization: Bearer wrong" $BASE/projects` | 401，`{code:401,message:"invalid admin token"}` |
| A3 | 正确 token 放行 | `curl -i -H "Authorization: Bearer $TOKEN" $BASE/projects` | 200，`{code:0,data:[...]}` |

### B. 项目 CRUD

| # | 验收项 | 怎么验证 | 预期 |
|---|---|---|---|
| B1 | 创建项目 | `curl -X POST $BASE/projects -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d '{"name":"测试","dbType":"postgresql","dbConfig":{"host":"localhost","port":5432,"user":"postgres","password":"x","database":"y"}}'` | 201，返回 `projectId` 以 `proj_` 开头，总长 21 |
| B2 | projectId 格式 | 看返回的 `projectId` | `proj_` + 16 位字符，例 `proj_GO062CDfsGrkkDu8` |
| B3 | 项目列表 | `curl -H "Authorization: Bearer $TOKEN" $BASE/projects` | 200，数组按 createdAt 倒序 |
| B4 | 项目详情 | `curl -H "Authorization: Bearer $TOKEN" $BASE/projects/<pid>` | 200，单条完整记录 |
| B5 | 更新项目名 | `curl -X PUT ... -d '{"name":"新名字"}'` | 200，`name` 变为新值 |
| B6 | 软删项目 | `curl -X DELETE ...` | 200，`status=false` |
| B7 | 软删后访问被拒 | 删完再 `GET /$BASE/projects/<pid>/tables` | 403 `project is disabled` |
| B8 | 不存在项目 404 | `curl $BASE/projects/proj_nonexistent` | 404 |

### C. 表 CRUD

| # | 验收项 | 怎么验证 | 预期 |
|---|---|---|---|
| C1 | 建表 | `POST /$BASE/projects/<pid>/tables -d '{"tableName":"album","displayName":"专辑"}'` | 201，返回完整表记录 |
| C2 | 重复表名 | 再 POST 一次相同 `tableName` | 409 `table "album" already exists` |
| C3 | 非法表名 | `tableName:"Album"`（大写）或 `"1abc"` | 400，zod 报 `tableName must be snake_case...` |
| C4 | 表列表 | `GET /$BASE/projects/<pid>/tables` | 200，数组 |
| C5 | 表详情 | `GET /$BASE/projects/<pid>/tables/album` | 200，带 `fields` 数组 |
| C6 | 更新表 displayName | `PUT ... -d '{"displayName":"新名"}'` | 200，displayName 变 |
| C7 | tableName 不可改 | PUT body 里传 `"tableName":"newname"` | 被 zod 忽略，DB 里 tableName 不变 |

### D. 字段 CRUD

| # | 验收项 | 怎么验证 | 预期 |
|---|---|---|---|
| D1 | 加主键字段 | `POST .../fields -d '{"fieldKey":"id","displayName":"ID","fieldType":"number","isPrimary":true,"primaryKeyStrategy":"auto_increment"}'` | 201，`primaryKeyStrategy` 正确落库 |
| D2 | 加普通字段（带约束） | `fieldKey:"name", fieldType:"text", isRequired:true, lengthLimit:100` | 201，约束都存上 |
| D3 | 加 select 字段带 options | `fieldType:"select", options:["a","b","c"]` | 201，options 数组原样返回 |
| D4 | 主键缺 strategy | `isPrimary:true` 但不传 `primaryKeyStrategy` | 400 `primary key field must specify primaryKeyStrategy` |
| D5 | 非主键带 strategy | 不传 `isPrimary` 但传 `primaryKeyStrategy` | 400 `non-primary field must not set primaryKeyStrategy` |
| D6 | 重复 fieldKey | 再 POST 一次 `fieldKey:"name"` | 409 |
| D7 | 字段列表按 sortOrder | GET fields | 200，按 sortOrder 升序 |
| D8 | 更新字段 displayName | PUT `{"displayName":"新"}` | 200，fieldKey 不变 |
| D9 | fieldKey 不可改 | PUT body 传 `"fieldKey":"newkey"` | 被 zod 忽略 |
| D10 | 删字段 | DELETE `.../fields/name` | 200 |

### E. 级联与一致性

| # | 验收项 | 怎么验证 | 预期 |
|---|---|---|---|
| E1 | 删表级联删字段 | 表下有 N 个字段时 DELETE 表 | 200，`data.deletedFields = N` |
| E2 | 级联后字段消失 | 删表后 GET fields | 404 `table not found` |

### F. 工程化

| # | 验收项 | 怎么验证 | 预期 |
|---|---|---|---|
| F1 | 类型检查通过 | `pnpm typecheck` | 零错误 |
| F2 | lint 通过 | `pnpm lint` | 0 error（1 个 complexity warning 可接受） |
| F3 | 格式检查通过 | `pnpm format:check` | `All matched files use Prettier code style!` |
| F4 | Prisma schema 合法 | `pnpm db:validate` | `The schema is valid` |
| F5 | pre-commit 钩子激活 | `git config core.hooksPath` | 返回 `.husky/_` |

### G. 审计日志

| # | 验收项 | 怎么验证 | 预期 |
|---|---|---|---|
| G1 | 每次写操作打日志 | 跑一次 create/update/delete，看服务端 stdout | 单行 JSON，带 `timestamp/action/operator/projectId/tableName/fieldKey/before/after` |
| G2 | 删表带级联计数 | 删表那条日志 | 带 `cascadedFields: N` 字段 |

## 三、本地启动

```bash
# 1. 起 PG（首次）
docker run -d --name schemaflow-pg \
  -e POSTGRES_PASSWORD=schemaflow123 \
  -e POSTGRES_DB=schemaflow_meta \
  -p 5432:5432 \
  postgres:16-alpine

# 之后每次启动
docker start schemaflow-pg

# 2. 装依赖（首次）
pnpm install

# 3. 跑迁移（首次）
pnpm db:m

# 4. 起服务
pnpm dev
# → http://localhost:3000

# 5. curl 时带
# -H "Authorization: Bearer change-me-to-a-long-random-string"
```

`.env` 示例见 `.env.example`，至少需要 `ADMIN_TOKEN` 和 `DATABASE_URL`。
