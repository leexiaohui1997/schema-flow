### 3. 四个边界情况处理策略

**（1）加 NOT NULL 字段到有数据的表**
- 策略：**报错提示**——如果用户加 NOT NULL 字段但没给 defaultValue，直接 400 报错："NOT NULL 字段必须提供 defaultValue，或允许 NULL"
- 理由：PG 不允许 `ADD COLUMN xxx NOT NULL` 不给默认值，应用层提前拦住，比 PG 原始错误友好

**（2）加 unique 字段到有重复数据的表**
- 策略：**把 PG 错误转成友好提示**——CREATE UNIQUE INDEX 失败时，捕获 PG 错误码，返回 409："现有数据有重复，无法加唯一约束"
- 理由：用户需要知道为什么失败，而不是看到 PG 的原始错误

**（3）ALTER COLUMN 缩窄长度（255→100）**
- 策略：**把 PG 错误转成友好提示**——ALTER COLUMN 失败时，返回 400："现有数据超过新长度限制，无法缩窄"
- 理由：同上

**（4）先DDL成功、prisma.field.create()失败**
- 策略：**标注为已知限制**——文档里写一句："极少见情况下（元数据库写入失败），可能出现物理表有列但元数据没记录的情况。出现时手工修复即可。"
- 理由：这个概率极低（Prisma 写元数据库失败的概率很小），不值得做自动 reconciliation

---

### 4. 并发行为

两个用户同时给同一张表加字段，PG 的 ALTER TABLE 会拿 ACCESS EXCLUSIVE 锁，第二个会阻塞。

**策略：不加超时/排队机制，文档里说明行为即可。**

理由：
1. 并发 DDL 本身就是低频操作，不会经常发生
2. PG 自己会串行执行，不会出错
3. 加超时/排队机制复杂度高，收益低

---

### 5. 首字段非主键的窗口期

从第一个字段创建到主键字段加进来之间，这张表物理存在但 CRUD 不可用。

**策略：前端调用时返回 400 "表未就绪：缺少主键字段"，不要返回 500。**

理由：
1. 这个窗口期很短——用户加完第一个字段后马上就会加主键字段
2. 500 是服务器错误，会让人以为系统挂了
3. 返回 400 + 明确提示，用户知道要先加主键字段

### 一、规划方回复的几点观察

**1. number = INTEGER 意味着不支持小数。**

映射表里 `number → INTEGER`、`auto_increment → SERIAL`。这意味着金额、小数、浮点数都存不了。13 种 fieldType 里没有独立的 decimal/float 类型，所以这是设计选择不是 bug。但应该在文档里标注一句"number 类型只支持整数，小数场景后续再加"，否则用户配了 `price` 字段填 `19.99` 会默默被截断。

**2. defaultValue 不改列 DEFAULT 约束——推迟到后续。**

规划方补了一句："defaultValue 改了不改列的 DEFAULT 约束，只改元数据里的配置。列默认值约束在阶段三不做。" 这个推迟可以接受，但要意识到：元数据里的 defaultValue 和物理列的 DEFAULT 约束会不一致。应用层注入 defaultValue 的逻辑（阶段二已实现）会补上这个缺口，所以用户感知不到。OK。

**3. TIMESTAMPTZ 选得对。**

`datetime → TIMESTAMPTZ` 而不是 `TIMESTAMP`，这是 PG 里正确的选择（带时区，无时区的 TIMESTAMP 在跨时区部署时会踩坑）。

### 二、开发者问题表态

**text 没设 lengthLimit 时是 TEXT 还是 VARCHAR(255)？**

规划方写的是"VARCHAR(255)，长度从 lengthLimit 来，默认255"——字面读是永远 VARCHAR(n)，n 默认 255。开发者的理解是"有 lengthLimit 就 VARCHAR(n)，没有就 TEXT"。

**我支持开发者的理解（方案 B：没设 lengthLimit 就 TEXT）。** 理由：

1. 没设长度限制的 text 字段，就是让用户随便写，强行卡 255 不合理
2. richtext 已经是 TEXT，text 不设长度也用 TEXT，语义一致
3. 用户真要卡长度，自己设 lengthLimit 就行

所以映射表应该改成：

| fieldType | 有 lengthLimit | 没设 lengthLimit |
|---|---|---|
| text / select / password / email | VARCHAR(n) | TEXT |
| url / file | VARCHAR(500) | VARCHAR(500) |
