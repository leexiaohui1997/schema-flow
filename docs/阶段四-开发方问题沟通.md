## 问题 2：DbAdapter 接口方法

规划细则里写了四个方法：`query / insert / update / delete`。

但阶段二的 `data.ts` 里直接用 `client.query(sql, params)`，不分 insert/update/delete。

**开发方建议：统一成一个 `query(sql, params)` 方法。**

理由：
- PG 的 pg 库和 MySQL 的 mysql2 都是用 query 方法，结果集自动返回
- insert/update/delete 的区别在 SQL 本身，不在 API
- 接口更简单，上层不用判断调哪个方法

```ts
interface DbAdapter {
  query(sql: string, params: unknown[]): Promise<{ rows: any[]; rowCount: number }>
  end(): Promise<void>
}
```

---

## 问题 3：_ctime/_mtime 和 trigger 语法差异

PG 和 MySQL 的自动时间戳机制不一样：

| 功能 | PG 语法 | MySQL 语法 |
|---|---|---|
| _ctime 默认值 | `_ctime TIMESTAMPTZ NOT NULL DEFAULT NOW()` | `_ctime DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP` |
| _mtime 默认值 | `_mtime TIMESTAMPTZ NOT NULL DEFAULT NOW()` | `_mtime DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP` |
| mtime trigger | `CREATE FUNCTION + CREATE TRIGGER` | 不需要 trigger，ON UPDATE 自动处理 |

**开发方确认：** MySQL 生成器自己处理 _ctime/_mtime，不用写 trigger，对吧？

## 问题 4：现有代码改造范围

现在 `dbConnection.ts` 返回 `pg.Pool`，`data.ts` 里直接 `client.query(sql, params)`。

改成 DbAdapter 后：
- `dbConnection.ts` 改成返回 `DbAdapter` 接口
- `data.ts` 里的 `client.query(sql, params)` 改成 `adapter.query(sql, params)`
- 返回值结构要统一（PG 返回 `{ rows, rowCount }`，MySQL 返回什么？）

**开发方确认：** MySQL 的 mysql2 结果集和 pg 不一样，要包一层统一成 `{ rows, rowCount }`？

## 规划方回复（2026-10-26）

### 问题1：MySQL 环境

**要本地起 MySQL Docker 容器。** 配置如下：

- 镜像：`mysql:8`
- 端口：`3306`（默认）
- 用户：`root`
- 密码：`root123`

Docker 命令参考：
```bash
docker run -d \
  --name schemaflow-mysql \
  -e MYSQL_ROOT_PASSWORD=root123 \
  -e MYSQL_DATABASE=schemaflow_biz_mysql \
  -p 3306:3306 \
  mysql:8
```

### 问题2：DbAdapter 接口方法

**同意开发方建议，统一成一个 `query` 方法。**

理由：
1. PG 和 MySQL 都是用 query 方法，结果集自动返回
2. insert/update/delete 的区别在 SQL 本身，不在 API
3. 接口更简单，上层不用判断调哪个方法

最终接口：
```ts
interface DbAdapter {
```

### 问题3：_ctime/_mtime 和 trigger 语法差异

**确认：MySQL 不用写 trigger，用 `ON UPDATE CURRENT_TIMESTAMP` 自动处理。**

MySQL 的 `DATETIME ... ON UPDATE CURRENT_TIMESTAMP` 比 PG 的 trigger 简单多了。MySQL 生成器自己处理就行。

---

### 问题4：现有代码改造范围

**确认：Adapter 要包一层，统一成 `{ rows, rowCount }`。**

PG 的 pg 库返回 `{ rows, rowCount }`，mysql2 返回的是 `[rows, fields]` 数组。Adapter 要包一层统一返回格式，上层代码不用关心底层差异。
